# 识别模型实验：Nemotron 3.5 对比 R2T2

日期：2026-09-24　分支：`exp/nemotron`（main 未改动识别代码）

## 结论

NVIDIA Nemotron 3.5 ASR Streaming 0.6B 在韩语、日语、英语上都不如当前的 Confucius4-R2T2 Q8，不替换。

- 韩语识别错误率在两个不同节目上都高 5–8 个百分点。
- 翻译质量随识别质量一起下降。
- 定稿延迟慢一个数量级。

## 为什么选它

**选型条件**：官方 GGUF，有 Q8 或 Q6 档；英、中、日、韩、西五种语言都要好；支持真正的流式识别。

调研时，只有 Nemotron 3.5 值得一试：
- NVIDIA 官方提供 Q8_0 GGUF，只有 0.74 GB。
- 原生流式架构：cache-aware FastConformer-RNNT，每次只处理新到的音频。
- 公开的 FLEURS 成绩（1.12 秒片段下）：西语 4.1、英语 7.9、日语 11.5、韩语 7.1、中文 19.3。其中中文偏弱。

其他候选都被排除：

| 候选 | 排除原因 |
|---|---|
| Qwen3-ASR（R2T2 的基础模型） | 用 160 ms 片段做只追加的流式识别时，准确度大幅下降。R2T2 模型卡在 AMI 会议录音上的数据：基础模型 24.8，R2T2 11.4 |
| Voxtral Realtime | 没有官方 GGUF，llama.cpp 也没有合并对它的支持 |
| Fun-ASR | 不支持西语 |
| 其余 | 不是真正的流式模型 |

## 环境

- **模型**：`nvidia/nemotron-3.5-asr-streaming-0.6b` 的官方 `q8_0.gguf`，742,090,464 字节，SHA-256 `3fc991d3…a070b1`，与 Hugging Face 上公布的一致。
- **运行时**：NVIDIA NeMo-Speech.cpp，版本 `97a15af`，以 `metal-server` 预设编译，跑在 Metal GPU 上。它不是 llama.cpp，r2d2 需要单独写一个后端。
- **对照**：R2T2 Q8，使用 main 的现行配置（160 ms 步进、8 秒窗口）。
- **计分**：`scripts/score.py`。韩语、日语按字计错误率，英语按词；两边使用同样的归一化方法。

## 测试一：离线流式准确度（旧测试集，6 段 × 5 分钟）

用 NeMo-Speech.cpp 的 `transcribe --stream` 跑 Nemotron，同时测了三档"每次多看后面多少音频"（右侧上下文）。R2T2 的数字取自修复 A 之后的实时测试。

| 错误率 | ko-1 | ko-2 | ja-1 | ja-2 | en-1 | en-2 |
|---|---|---|---|---|---|---|
| **R2T2 Q8** | **23.1%** | **23.1%** | **25.8%** | **26.7%** | **5.2%** | **11.5%** |
| Nemotron 160 ms | 28.2% | 28.4% | 27.4% | 28.1% | 6.3% | 13.3% |
| Nemotron 560 ms | 27.2% | 26.9% | 27.9% | 28.0% | 5.5% | 12.3% |
| Nemotron 1.12 s | 27.4% | 26.9% | 28.0% | 27.0% | 5.7% | 13.2% |

- 18 组比较中，Nemotron 没有一组赢。韩语差距最大，为 4–5 个百分点；日语和英语只差 0.3–2 个百分点。
- 排除了数字写法造成的偏差：Nemotron 在这些音频上一个阿拉伯数字都没输出，把数字从参考、R2T2 和 Nemotron 三边都删掉后重算，差距不变。
- 局限：
  - 每种语言的两段都出自同一个视频。
  - 日语参考是 YouTube 自动字幕，本身有错。
  - 测试集没有中文和西语。

## 接入应用（分支 `exp/nemotron`）

提交 `e9da3af`、`b6e9b9b`，工作目录是 git worktree `../r2d2-nemotron`。

- **分流**：识别语言选韩语或日语时改用 Nemotron，其余语言仍用 R2T2。
- **运行方式**：`r2d2/nemotron.py` 把 `nemo-speech serve` 作为本机私有子进程启动，通过它的实时 WebSocket 通信。
- **定稿方式**：开启停顿断句（静音 800 ms 结束一句）后，模型对每句话输出带标点的定稿，作为确认文本；未结束的部分作为草稿显示。确认文本只追加，所以翻译管线不用改。
- **界面**：会话信息行和结果卡片上标明本次用的是 Nemotron；导出记录中注明模型。
- **测试**：新增分流测试，共 85 个测试全部通过。
- **不支持**：识别上下文和热词提示对 Nemotron 不起作用。

## 测试二：通过应用实测，新增数据源并开启翻译

**新数据源**：《문명특급 MMTG》（SBS），4 人综艺访谈，有插话、笑声，还有后期加的音效和背景音乐。取前 10 分钟切成两段：ko-3 是 0:00–5:00，开场生日派对，常有多人同时说话；ko-4 是 5:00–10:00，正常聊天。
- 韩语人工字幕接近逐字稿：每 5 分钟统计一次，和自动字幕的字数之比在 0.94–1.03 之间。
- 同一视频带人工中文翻译，是测试集里第一份翻译参考。

**测试方式**：两个模型都通过应用本身跑，按真实语速推送音频，开启翻译。每次只运行一个服务，跑完即停。

| ko-3 / ko-4 | R2T2 Q8 | Nemotron |
|---|---|---|
| **识别错误率** | **29.3% / 20.6%** | 35.5% / 28.4% |
| 文字上屏延迟 p50（含草稿） | **0.26 / 0.23 秒** | 0.48 / 0.47 秒 |
| 文字定稿延迟 p50 | **0.47 / 0.45 秒** | 5.5 / 4.5 秒 |
| **翻译 chrF**（和人工中文比） | **15.9 / 18.5** | 14.6 / 16.4 |
| 翻译延迟 p50 | 544 / 221 ms | 537 / 547 ms |
| 送去翻译的句子数 / 长度中位数 | 32 / 56 句，66 / 37 字 | 83 / 71 句，17 / 22 字 |

**翻译上限**：用 HY-MT 逐条翻译人工韩语字幕（相当于识别完全正确），chrF 为 **22.2 / 20.6**。

- **chrF 的含义**：按字符片段计算和人工译文的重合度，满分 100。人工译法比较自由，同一个意思换了说法也会扣分，所以这个分数只用来比较高低。
- **翻译损失**：R2T2 管线离上限差 2–6 分，Nemotron 差 4–8 分。
- **切句**：Nemotron 按停顿切出的句子更短、更碎，没有像预期那样帮到翻译。
- **旧数据上的同样现象**：旧测试集 ko-1 通过应用实测时也一样，Nemotron 错误率 28.2%，定稿延迟 p50 4.1 秒、p90 12.1 秒。

## 总评

| | R2T2 Q8 | Nemotron 3.5 Q8 |
|---|---|---|
| 韩语识别（两个来源、4 段） | 好 | 差 5–8 个百分点 |
| 日语、英语识别 | 好 | 略差 0.3–2 个百分点 |
| 翻译质量 | 较好 | 略差 |
| 定稿延迟 | 约 0.5 秒 | 约 5 秒，取决于停顿 |
| 模型体积 | 1.83 + 0.35 GB | 0.74 GB |
| 运行时 | llama.cpp | 另需 NeMo-Speech.cpp |

Nemotron 只在体积和运算量上占优，准确度和定稿延迟都不如 R2T2，不替换。

- **存档脚本**：在 `docs/experiments/nemotron-asr-scripts/`，运行时要放回原位置。

| 存档文件 | 原位置 | 用途 |
|---|---|---|

| `mt_ref.py` | `artifacts/bench/mt_ref.py` | 翻译上限 |
