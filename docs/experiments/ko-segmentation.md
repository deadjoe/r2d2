# 韩语切句实验：laya 与 Jev 对比 main 现状

日期：2026-09-24　分支：`exp/laya-segment`、`exp/jev-segment`（main 未改动）

## 结论

在韩语切句上，laya-multilingual 和 Jev 直接拿来用（不做训练）都不如 main 现状。和 main 切同样多刀时，main 切对的比例是 0.62 / 0.58，Jev 是 0.41 / 0.28，laya 是 0.24–0.35。两种模型都不接入。

## 背景

- **问题**：韩语、日语的识别输出很少带句末标点，`split_sentences` 只能在已有标点处切，否则满 120 个加权字符（`MAX_SEGMENT`）硬切。硬切常落在句中，影响翻译。
- **设想**：用"判断型小模型"判断每个词间位置是否句子边界。这类模型一次前向即可在给定选项间打出概率，不生成文字。
- **范围**：只测韩语。韩语有人工字幕可作标准答案；日语只有自动字幕，而且韩语已经得出结论，所以没测。

## 数据与标准答案

- 音频：测试集 ko-1、ko-2，各 5 分钟，多人对话，有背景噪声和笑声。
- 标准答案：人工字幕每条之间的边界。标准分两档：
  - **全部边界**：每条字幕的结尾都算"该切"。
  - **严格边界**：只算以 `. ? ! …` 结尾，或与下一条相隔至少 0.3 秒的字幕结尾。其余字幕边界多是为了显示长度而拆开的，不算对也不算错，直接跳过。
- 指标：
  - AUROC：模型能否把"该切"和"不该切"的位置分开。0.5 等于随机，1 表示完全分开。
  - P（精确率）：切的地方里切对的比例。
  - R（召回率）：该切的地方里切到的比例。
  - F1：P 和 R 的综合分。

## 实验一：laya-multilingual（分支 `exp/laya-segment`）

**模型与环境**
- `convaiinnovations/laya` 的 `multilingual` 子目录：mmBERT-base，322M 参数，权重 647 MB。
- laya 0.3.11，torch 2.14，transformers 5.17，装在隔离的虚拟环境 `artifacts/laya/venv`，不进项目依赖。

**用法要点**（依据模型卡和源码）
- 模型的输入格式是 `[CLS] 问题 [SEP] [MASK]选项… [SEP] 原文 [SEP]`，在各选项之间做 softmax。
- 强制指定 `device="cpu"`。laya 在 Mac 上默认用 MPS，会和识别抢 GPU。
- 主要用中性选项键的 `choice`，因为模型卡指出 `noul` 会偏向标签本身；另外也测了 1 个 `noul` 问法和 1 个 `score` 问法作对照。
- 原文长度控制在截断范围内。

**测试 1：人工字幕原文去掉标点，逐个词间位置判断**

候选位置：ko-1 有 579 个，ko-2 有 619 个。

| 问法 | ko-1 AUROC（全部 / 严格） | ko-2 AUROC（全部 / 严格） |
|---|---|---|
| 左侧文本是否完整句 | 0.50 / 0.55 | 0.51 / 0.52 |
| 同上，问题中提示韩语句末词尾 | 0.50 / 0.52 | 0.52 / 0.51 |
| `左 ‖ 右`，‖ 处是否句末 | 0.48 / 0.52 | 0.47 / 0.50 |
| 同上，提示句末词尾 | 0.48 / 0.56 | 0.49 / 0.47 |
| JSON：已说部分 / 后续词 | 0.49 / 0.49 | 0.46 / 0.50 |
| `noul`：‖ 处是否句末 | 0.53 / 0.60 | 0.49 / 0.51 |

**测试 2：整条字幕与截去尾部的同一条字幕对比**

这是对模型最有利的设置，共 217 对。
- AUROC 在 0.43–0.55 之间。
- 唯一例外是问题中提示句末词尾的问法，达到 0.71。但它换回测试 1 的逐词设置后，回落到 0.50。

**速度**：CPU 批量（每批 16 条）时，每个位置 17–26 ms；单条调用约 50 ms。

**结论**：接近随机。这与模型卡自述一致：基础模型在没训练过的判断上接近随机，需要微调。

## 实验二：Jev（分支 `exp/jev-segment`）

**模型**：TypeSafe 云端 API，模型 `jev-1.13.0`，端点 `POST https://api.typesafe.ai/v1/systemone`。官方文档称英语效果最好，其他语言"能处理但不如英语"。

**用法**：照官方"结构恢复"示例的写法。
- 每次请求放 50 个词，在每个候选位置插入编号 `[i]`。
- 每个编号问一个 `noul`，所有问题放在同一次请求里。
- 相邻窗口重叠 10 个词，保证每个位置两侧都有上下文，并且只打一次分。

**测试：人工字幕原文去掉标点**

候选位置：ko-1 有 578 个，ko-2 有 618 个。

| 问法 | ko-1 AUROC（全部 / 严格） | ko-2 AUROC（全部 / 严格） | 最好 F1（全部） |
|---|---|---|---|
| [i] 后是否开始新句 | 0.66 / 0.70 | 0.67 / 0.67 | 0.47 / 0.46 |
| [i] 是否切在句中（取反） | 0.62 / 0.63 | 0.62 / 0.61 | 0.45 / 0.42 |

作为对照，每个位置都切时，F1 约为 0.40。

**速度与成本**
- 每次请求约 0.7–0.8 秒；第一次单独调用约 1.7 秒。
- 一段 5 分钟的音频约 5.5–7.5 万 token，按官方价格 $0.042 / 百万 token 计，不到 1 美分。

**结论**：Jev 比 laya 强，有一定信号，但离可用很远。

## 实验三：同一份真实识别输出上，与 main 对比

**输入**：Q8 实时识别的最终文本（`artifacts/bench/q8-ab/ko-*.json`），带识别本身输出的少量标点。
- ko-1 共 541 个词；ko-2 共 618 个词。
- 人工字幕边界按字符对齐映射到识别文本的词间位置，每段各映射成功 140 条（字幕共 146 / 147 条）。

**各方法怎么切**
- **main**：按 `LiveTranslation.update` 的实际方式，逐条重放识别的更新，调用 `split_sentences`。
- **Jev、laya**：给每个词间位置打分。laya 取测试 1 中的两种问法。

### 同样刀数下的比较（关键结果）

让模型只在分数最高的前 K 个位置切，K 等于 main 的刀数（ko-1 为 37，ko-2 为 50）：

| 方法 | ko-1 P（全部 / 严格） | ko-2 P（全部 / 严格） | 最长一段（字，ko-1 / ko-2） |
|---|---|---|---|
| **main 现状** | **0.62** / 0.30 | **0.58** / 0.34 | 52 / 51 |
| Jev | 0.41 / 0.19 | 0.28 / 0.18 | 255 / 172 |
| laya：左侧是否完整句 | 0.35 / 0.23 | 0.24 / 0.10 | 436 / 381 |
| laya：`noul` | 0.35 / 0.20 | 0.32 / 0.13 | 286 / 198 |

### 各用最优阈值时的比较

每个模型用另一段音频上 F1 最好的阈值：

| 方法 | ko-1 P / R / F1 | ko-2 P / R / F1 | 段数（ko-1 / ko-2） | 每段字数中位数 |
|---|---|---|---|---|
| main 现状 | 0.62 / 0.17 / 0.27 | 0.58 / 0.21 / 0.31 | 38 / 51 | 48 / 33 |
| Jev | 0.34 / 0.68 / 0.46 | 0.31 / 0.65 / 0.42 | 263 / 292 | 3 / 3 |
| laya（每段取 F1 较高的问法） | 0.25 / 0.89 / 0.39 | 0.23 / 0.95 / 0.37 | 474 / 570 | 3 / 2 |
| 人工字幕本身 | — | — | 133 / 140 | 10 / 11 |

模型的 F1 更高，只是因为它们几乎每隔一个词就切一刀，每段中位数只有 2–3 个字。这样的碎片送去翻译，比现在的整句差得多，所以这里的 F1 不代表实际效果。

### main 现状的特点

- 切点中 15/37（ko-1）和 31/50（ko-2）落在识别输出自带的 `. ? !` 上，这部分基本都对。
- 其余切点来自 120 字上限，会退到逗号或空格处，没有一刀切进词中间，但常落在句中。
- 召回率只有约 0.2：大部分真实边界没有切到，句子偏长。这是现状真正的不足，但两种模型都没能改善。

## 总评

| | laya-multilingual | Jev | main 现状 |
|---|---|---|---|
| 区分边界的能力（AUROC） | 约 0.5，等于随机 | 0.66–0.70 | —（规则） |
| 同刀数时切对的比例 | 0.24–0.35 | 0.28–0.41 | **0.58–0.62** |
| 片段长度可控 | 否（最长 436 字） | 否（最长 255 字） | 是（不超过 120 加权字符） |
| 运行位置 | 本地 CPU，每个位置约 20 ms | 云端，每次请求约 0.8 秒 | 本地，几乎零开销 |
| 隐私 | 本地 | 对话内容上传第三方 | 本地 |

- 两种模型直接拿来用，都不如 main 现状，不接入。
- 若还要走这类模型，唯一方向是用大量带分句边界的韩语、日语对话字幕微调 laya。但 Jev 直接用也只到 0.7，微调能否超过 main，没有把握，成本也不小。
